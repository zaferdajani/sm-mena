# Sawwiq agency journey, as built (evidence only, no opinions)

Build: local production build of the current checkout (`registration-setup-2026-09-29` stamp in footer), PGlite, no credentials, `LAUNCH_PHASE` unset (= `registration`, the default per docs/51), `prelaunch_home=off`. Viewport 390x844 Arabic (`/ar`) unless stated; English 390 (`/en`) and 1280 desktop repeated for the key screens. Headless Chromium, localhost, so server timings are best case (no network latency, warm PGlite).
Screenshots: `/tmp/claude-0/-home-user-sm-mena/bf648f73-8b93-578c-890e-e7a636964ebf/scratchpad/ux/shots/` (all full page; note that a full-page capture of a sticky header/bottom nav/floating "Help" button repeats or overlaps them in the middle of the image; that is a capture artifact, not measured on a live scroll).

## Headline facts
- There is NO email code, NO email verification and NO separate password step for a provider (agency/freelancer). Sign-up is one 3-step form, then one submit (password set in the same form). Email codes (`AUTH_SHOW_CODES`) exist only on the business-owner/client path (`/owner`, button "Send the code"), not for agencies.
- After "Create page" the user lands directly in `/portfolio-setup` (5-step wizard) outside the Studio layout.
- The wizard's last button says "Save my portfolio" (not "Publish"). In the registration phase the page is PRIVATE: the project is saved but an anonymous visitor to `/a/<handle>` gets HTTP 404 (shot 20). To be visible, the user must go to `/studio/publication`, pick "Allow public publication", tick an acknowledgement, and save. Only then does the public profile render (shots 23, 53).
- Studio home checklist shows all three items ("Introduce your services", "Add work or a package", "Choose your profile visibility") already ticked right after the wizard, even though visibility was never chosen (private default counts as done, per docs/51).
- Services are asked twice (join step 2 and wizard step 1) though the join answers are prefilled in the wizard (verified in English: "SEO" chosen at join appeared in wizard step 1). Name is prefilled as well. WhatsApp/email asked once.

## Click / field / page-load totals to "portfolio published with at least one project" (Arabic, shortest valid path, upload route)
Counting rules: click = any tap on a button, card, checkbox, radio or link (text-field focusing not counted; picking files in the OS dialog counted as 1). Field = a visible input/choice the user must or may act on; "required" = blocks progress. Screen = distinct view. Page load = distinct URL navigation (landing `/ar`, `/ar/join`, `/ar/portfolio-setup`, `/ar/studio/publication`); wizard steps and join steps change screen without a URL change.

Text entries actually typed on that path: 8 (agency name, username, WhatsApp, email, password, client name, project name, contribution) + 1 file selection (1-10 images). As I ran it (with logo upload, bio, a service chip) it was 22 clicks and 11 inputs; the shortest path above leaves optional fields blank. Not counted: waiting, rechecking, the Arabic "Show it in English" bar (dismiss = 1 more click if closed).

Measured timings (localhost): landing 2.0 s first load (cold), later routes 0.8-1.1 s to network-idle; join -> account created 0.47 s; wizard step saves 0.23 s each; uploading two 1200x900 PNGs 1.9 s; Save my portfolio 0.83 s; publication save ~1.5 s; studio/new "Publish" ~3 s to finish; PDF read of a 3-page PDF ~6 s (client-side).

## Dead ends / guesses / waits / docs-only items
- Landing is ~7 screens long before the CTA repeats; its 5 identical CTAs all lead to `/join` (the "who are you" chooser `/start` is bypassed).
- Joining asks for the 18+ box and terms box together at the end, after 2 steps of unrelated questions; there is no email/code step, so "email, code, password" in the journey brief do not exist for agencies in this build.
- Native browser validation bubbles only (language of the bubble follows the browser, not the page); the wizard uses a generic "Something in this step isn't right" banner at least for the empty client name.
- Wizard 'Source' step: "Connect a social account" has no working option for any of 5 platforms (docs/53 only; the user sees "not registered yet"); an import click in the Behance fixture path opens a panel and requires a second click on a project row.
- "Save my portfolio" does not make the portfolio visible; the 404 for the public and the three-way visibility choice are explained inside the wizard note, and in `docs/51-registration-phase.md` (private preview as a real permission, phase overlay) which the page text only partially mirrors.
- Wizard shows "Step n of 5" while the Studio home shows its own checklist of 3 items; the two progress models are separate.
- Studio home claims all 3 setup tasks done immediately after the wizard.
- Studio nav tab strip scrolls horizontally on all widths including 1280 (last tab cut off: "C..." in `70-desk-studio-home.png`).
- Duplicate Behance entry points: join aside note, wizard step 2 import, studio home card, studio/new box, studio/import page, setup guide button.
